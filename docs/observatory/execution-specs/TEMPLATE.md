## Implementation authorization

State the exact condition that must be met before implementation begins.

## Outcome

State the technical result and which acceptance criteria it satisfies.

## Current state

List verified current files, interfaces, data stores, and constraints. Separate
existing behavior from proposed behavior.

## Architecture and boundaries

Name components, responsibilities, trust boundaries, and communication paths.
Include a small ASCII diagram for multi-component flows.

## Data contracts

Provide exact input, intermediate, output, error, version, and validation
contracts. Link to standalone schemas.

## Algorithm design

Define preprocessing, features, formulas, normalization, aggregation,
uncertainty, suppression, and degraded behavior.

## Implementation tasks

Number ordered tasks. Give repository paths, dependencies, owner roles, and
completion conditions.

## Test and benchmark plan

Cover unit, property, integration, migration, regression, benchmark,
performance, privacy, and failure tests as applicable.

## Operational design

Define schedule, idempotency, concurrency, retries, dead-letter behavior,
lineage, health, metrics, alerts, backfill, restore, and rollback.

## Security, privacy, rights, and compliance

Define access, secrets, encryption, source rights, retention, deletion,
publication, audit, and incident behavior.

## Release strategy

Define backfill, shadow, comparison, approval evidence, cutover, rollback, and
retirement.

| --- | --- | --- | --- |
| Failure | Signal | Fail-closed behavior | Recovery action |

## Definition of done

Use pass/fail closure requirements covering code, data, tests, docs, evidence,
operations, and approval.
